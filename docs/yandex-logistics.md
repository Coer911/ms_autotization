# Маршрутный лист на Яндекс Диске

Две выключенные записи в `config.yaml`: `logistics_sheet` и `logistics_publish`.
Живой Диск и живой МойСклад этой сборкой не вызывались. Токен в репозиторий не входит.

## Как устроено

Вебхук заказа покупателя только проверяет переход в «ПОДТВЕРЖДЕН / ОЖИДАЕТ СБОРКИ»
из другого статуса. Первый снимок и отмена заказом не становятся. Дата маршрута —
следующий понедельник–пятница по Москве после `auditContext.moment` вебхука.
`customerorder.updated` датой перехода не используется. Если момента аудита нет
(так бывает у страховочного опроса), заказ остаётся на ручной проверке: дату хаб не угадывает.

На этом шаге Диск не вызывается. Заказ пишется в базу хаба. Повтор тот же заказ не дублирует.

Отдельная задача `logistics_publish` в `at` (по умолчанию 07:00 Europe/Moscow) собирает
заказы этой даты в новый файл `Маршрутный лист — ДД.ММ.ГГГГ.xlsx` и загружает его
в `folder`. Загрузка идёт официальным REST Диска с `overwrite=false`. Уже лежащий файл
не перезаписывается и не удаляется. После загрузки хаб хранит путь, id (им в REST служит
путь), состав и контрольные суммы. Повтор после рестарта файл заново не создаёт.
Если ответ Диска не подтвердил файл, повтор сначала сверяет путь и md5. Не совпало —
ошибка, не запись поверх.

Поздний заказ на уже опубликованную дату сохраняется как `LATE_ORDER`. В файл он не
добавляется. Если задан `notify_chats` и настроен Telegram, логист получает сообщение.
Иначе запись видна в журнале запуска.

Колонки листа: №, Контрагент, Адрес доставки, Телефон, Часы приёмки (текст),
Комментарий логисту, Выполнено. Скрытый лист `_hub` хранит id заказа, дату маршрута,
версию формата и id публикации. Редактор Яндекс Таблиц хаб не вызывает.

## Переменные

Значения здесь не приводятся.

| Имя | Где | Что это |
|---|---|---|
| `YANDEX_DISK_TOKEN` | окружение | OAuth отдельного приложения. Права только `cloud_api:disk.read` и `cloud_api:disk.write` |
| `folder` | `logistics_publish` в config.yaml | путь папки, например `disk:/маршрут-проба` |
| `at` | там же | время снимка, `ЧЧ:ММ` по Москве |
| `notify_chats` | `logistics_sheet` | чаты Telegram для позднего заказа; пустой список — только журнал |
| `hours_field`, `phone_field` | `logistics_sheet` | имена доп. полей заказа; пустые — часы не пишем, телефон берётся у контрагента |

Почтовый токен и `mail:*` к Диску не подходят. Дисковый токен почту не открывает.
Это разные приложения: у одного OAuth-приложения не бывает двух рабочих токенов с разным набором прав.

## Первый запуск на отдельной папке

1. Создать OAuth-приложение «для доступа к API», не то, которым ходит почта.
   В доступах отметить чтение и запись Диска: `cloud_api:disk.read`, `cloud_api:disk.write`.
   Права почты не добавлять.
2. Получить токен у себя и положить его в `YANDEX_DISK_TOKEN` на сервере. В чат и в git не отправлять.
3. На Диске создать пустую папку, не ту, где уже лежат боевые листы. Путь записать в `folder`.
4. Утвердить `at`. Сейчас в конфиге стоит `07:00`. Пока время не утверждено, в бой не включать.
5. Оставить `HUB_DRY_RUN=1` и обе записи `enabled: false`, пока пробный журнал не покажет
   `WOULD_COLLECT` и `WOULD_PUBLISH`. В этом режиме Диск не вызывается.
6. Вебхуки МойСклад этим изменением не ставятся. Их включают отдельно, когда пробный прогон понятен.
7. Для боевой пробы на пустой папке включить обе записи. Существующий файл с тем же именем
   хаб не заменит: будет ошибка, файл останется как был.

`daily_upd` это не затрагивает.
