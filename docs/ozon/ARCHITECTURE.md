# Архитектура среза Ozon

Ozon живёт внутри одного хаба. Отдельного процесса, брокера и базы нет.

```text
Ozon Seller API  --POST /v4/posting/fbs/list-->  hub/ozon/client.py
                                                      |
                                               redact.py  (без персональных данных)
                                                      |
                                               match.py   (GET артикула, если есть токен)
                                                      |
                                               hub/storage/ozon.py  -->  /data/hub.sqlite3
```

Планировщик хаба вызывает `ozon_fbs_import` только после `enabled: true`. Слот `YYYY-MM-DD:{номер}` и `try_start` не дают второму запуску в том же интервале пройти повторно. На SQLite второй процесс хаба не поднимаем: писатель один, `HUB_ROLE=all`.

## Границы модулей

| Модуль | Можно | Нельзя |
|---|---|---|
| `hub/ozon/client.py` | один метод, список FBS v4 | ship, carriage, остатки, цены, возвраты, push |
| `hub/ozon/redact.py` | поля склада и строки | имя, телефон, адрес, финансы, сырой JSON |
| `hub/ozon/match.py` | `GET entity/product`, `GET entity/variant` | POST, PUT, создание карточек |
| `hub/ozon/fbs_import.py` | снимок в базу хаба | `set_state`, `set_fields`, документы |
| `hub/storage/ozon.py` | три таблицы на общем metadata | копия документа МойСклад |
| `hub/automations/ozon_fbs_import.py` | расписание, по умолчанию выключено | запись в МойСклад |

Клиент МойСклад не менялся. Сопоставление идёт через `MoySklad.find`. Если токена нет, строки получают `no_catalog`, а уже записанное сопоставление не затирается.

## Идемпотентность до документов

Пока хаб не создаёт документы, повтор закрыт тремя уровнями:

1. Первичный ключ отправления. Повтор обновляет ту же строку или не трогает её, если отпечаток данных Ozon тот же.
2. Строки снимка заменяются внутри той же транзакции. Удаление строки снимка не удаляет ничего в МойСклад.
3. Строка `ozon_operations` на ключ операции. Повторный INSERT гасится `ON CONFLICT DO NOTHING`.

Когда появятся отгрузка, возврат и списание, запись в МойСклад начнётся только после проверки, что документа с тем же `externalCode` ещё нет. Неясный ответ API не повод создавать второй документ.

## Конфликт с уже включёнными автоматизациями

`logistics_sheet` смотрит переход заказа в «ПОДТВЕРЖДЕН / ОЖИДАЕТ СБОРКИ» и не исключает Ozon. Заказы Ozon этот статус не получат.

`daily_upd` выключен. Если его включить, он отправит УПД по проведённым отгрузкам контрагентов ООО и ИП. Отгрузки Ozon до отдельного решения туда не входят: контрагент и договор ещё не заданы, документы не создаются.

## Что остаётся на бумаге

FBO, возвраты, отмена, списание и приём push описаны в `ACCOUNTING_RULES.md` и `ROADMAP.md`. Кода, который ходит в эти методы, в срезе нет.
