# Маршрутный лист

Плагин `logistics_sheet` добавляет заказ в файл Google Sheets на следующий рабочий
день, когда заказ **перешёл** в статус `ПОДТВЕРЖДЕН / ОЖИДАЕТ СБОРКИ` из другого
статуса. Заказ, который уже стоял в этом статусе в момент первого снимка хаба,
в лист не попадает.

В `config.yaml` автоматизация выключена (`enabled: false`). Этот файл не включает
её и не ставит вебхуки.

Секретов здесь нет. Ключ сервисного аккаунта живёт только в переменной окружения.

## Что нужно от владельца

1. Точное имя статуса заказа. Сверить: `python -m hub states orders`.
   Если имя отличается от `ПОДТВЕРЖДЕН / ОЖИДАЕТ СБОРКИ` (буква ё, другой хвост),
   вписать его в `state`. Id статуса из той же команды можно положить в `state_id`:
   тогда при наличии id в заказе сравнение идёт по id, имя остаётся запасным.
2. Id папки Drive → `folder_id`.
3. Id файла-шаблона → `template_file_id`.
4. Имя доп. поля заказа с часами приёмки → `hours_field`
   (`python -m hub fields orders`). Пока пусто, колонка «Часы приемки» не заполняется.
5. Если телефон лежит в доп. поле заказа, его имя → `phone_field`.
   Иначе хаб берёт городской телефон контрагента, а если он пуст — первый
   непустой телефон контактного лица.
6. JSON ключа сервисного аккаунта в `GOOGLE_SERVICE_ACCOUNT_JSON` (одна строка).
   Не в чат, не в git, не в `config.yaml`.

Без `template_file_id` файл не создаётся.

## Какой шаблон положить в Drive

Нужна одна вкладка со структурой дневного листа «06.03.2026», без живых заказов:

- строка 1: A1:B1 «МАРШРУТНЫЙ ЛИСТ», C1:D1 дата, E1:G1 исполнитель;
- строка 2: A «Гр.м.», B «Контрагент», C «Адрес», D «Телефон», E «Часы приемки»,
  F «Комментарий», G «Выполнено»;
- с строки 3 пусто.

Не класть в шаблон вкладки «Адреса», «Адреса скорая почта на 1 август» и старую
форму «08.09.2025». Если они есть в шаблоне, хаб удаляет их **только у копии**,
которую сам создал в этом же вызове, и только после того, как Drive подтвердил
id копии и служебную метку (`hub=logistics_sheet`, `route_date` равен дате
маршрута). Сам шаблон на запись не открывается. Строки 3–500 этой копии
очищаются тогда же, чтобы образец дня не уехал в новый файл.

Уже существующий файл на эту дату хаб не очищает и не переписывает. Второй файл
с тем же именем не создаётся. Если у файла нет листа `_hub`, индекс повреждён
(номер строки не число, строка выше 3-й, повтор id) или служебная метка не
совпала, запуск завершается ошибкой. То же самое, если на листе есть непустая
строка с 3-й и ниже, а её номера нет в `_hub`: смотрятся колонки A–G до конца
листа, не только B3:B20. Так бывает и при пустом индексе, и когда часть строк
уже с id, а соседняя без него. Запись заказа в этом случае не начинается.
Причина пишется в журнал. Такой файл чинит человек: восстановить лист и метку
или убрать файл. Автоматической миграции нет.

Исполнителя из заказов хаб не подставляет. Если ячейка E1 уже заполнена, она
остаётся. Дату в C1 он ставит равной дате маршрута (`дата доставки: ДД.ММ.ГГГГ`)
только при создании копии.

Имя файла: `Маршрутный лист — ДД.ММ.ГГГГ`. Повторно на ту же дату файл не создаётся.
Скрытый id заказа пишется на лист `_hub` и не сдвигает колонки A–G.

Колонка A «Гр.м.» и колонка G «Выполнено» хабом не заполняются и не сбрасываются.
Часы и комментарий, которые логист уже вписал, повторная синхронизация не затирает.
Часы приёмки («10-14», «09:00-18:00», «10:00–14:00» и любые другие) уходят в Google
как текст: `valueInputOption=RAW` и числовой формат ячейки TEXT, без разбора в дату.

Адрес пишется при первой вставке строки. Если в ячейке адреса уже есть текст,
повторная синхронизация его не меняет. Расхождение с адресом заказа попадает
только в журнал: вторая строка не создаётся, дата маршрута не пересчитывается.
Пустая ячейка адреса заполняется. Нет адреса доставки в заказе — строка не
создаётся, в журнале отчёт, юридический адрес не подставляется. Отменённый
заказ не добавляется.

## Google

Сервисный аккаунт, без domain-wide delegation.

1. Включить Google Sheets API и Google Drive API.
2. Создать сервисный аккаунт и скачать JSON ключ.
3. Положить JSON в `GOOGLE_SERVICE_ACCOUNT_JSON`.
4. Папку и файл шаблона расшарить на `client_email` из этого JSON с правом редактора.
   Сам email секретом не является, приватный ключ — является.

Права в коде:

- `https://www.googleapis.com/auth/spreadsheets` — ячейки копии;
- `https://www.googleapis.com/auth/drive` — увидеть расшаренную папку и скопировать
  шаблон. Более узкий `drive.file` чужие расшаренные файлы не видит.

Вызовы только к `folder_id` и `template_file_id`: поиск файла по точному имени,
копирование шаблона, правка копии. Файлы код не удаляет. Шаблон на запись не открывает.
Токен и заголовок Authorization в журнал не пишутся.

Успех боевой записи — только после ответа Google с id файла или подтверждённым
диапазоном ячеек. Иначе ошибка уходит в обычный повтор хаба.

## Как проверить, не трогая боевую папку

1. Оставить `HUB_DRY_RUN=1`. Так и стоит в `.env.example`.
2. Завести отдельную папку Drive и отдельный шаблон. Их id вписать в `config.yaml`.
   Боевую папку не указывать.
3. `enabled` пока не ставить в `true`, вебхуки не ставить
   (`python -m hub webhooks install` не запускать).
4. Поднять хаб и убедиться, что без JSON ключа процесс стартует, а `daily_upd` на месте.
5. Включить `logistics_sheet` на тестовой папке, всё ещё с `HUB_DRY_RUN=1`.
   В журнале ожидаются `WOULD_CREATE_ROUTE`, `WOULD_ADD_ORDER`, `WOULD_UPDATE_ORDER`.
   Файлов и строк в Google при этом нет. МойСклад читается, не пишется.
6. Боевую запись (`HUB_DRY_RUN=0`) делать только на этой тестовой папке и после того,
   как пробный журнал выглядит правильно. Снова без установки вебхуков: события
   можно поймать опросом или `python -m hub run logistics_sheet <номер>` на одном
   тестовом заказе.
