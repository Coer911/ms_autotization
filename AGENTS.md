# Правила для агента в этом репозитории

Совпадает с `CLAUDE.md`. Если правила расходятся, приоритет у `CLAUDE.md`, а по Ozon ещё у `docs/ozon/MASTER.md`.

## Хаб

- Перед коммитом: `python3 -m pytest -q` и `ruff check .`. Меняешь `hub/storage` или конкурентность — прогони и на PostgreSQL (`HUB_TEST_DATABASE_URL`).
- `docs/moysklad-api/` руками не править. HTTP к МойСклад только через `hub/moysklad/`.
- Запись в МойСклад из автоматизации только через `ctx.set_state` и `ctx.set_fields`. Наружу только через `ctx.channels`.
- Секреты только в окружении: не в коде, не в `config.yaml`, не в коммите, не в чате.
- Всё, что пишет клиентам или в МойСклад, начинается с `HUB_DRY_RUN=1`.
- Ответы API не выдумывать. Живой МойСклад из облачной сессии обычно недоступен: писать, что прогон был на `tests/fake_moysklad.py`.
- Ветка и pull request. В `main` не пушить: `main` выкатывается на Dockhost.
- Бот только читает МойСклад. Запись только по прямой просьбе и с подтверждением.
- Коммиты коротко и по-русски.

## Ozon, срез только на чтение

Решение: `docs/ozon/MASTER.md`. Роли: `docs/ozon/AGENT_ROLES.md`.

- Один хаб, один экземпляр, `HUB_ROLE=all`, база этого внедрения `/data/hub.sqlite3`.
- Не добавлять Supabase, Redis, отдельный PostgreSQL, Kubernetes и новые сервисы.
- Совместимость ядра с PostgreSQL не выкидывать и ядро под это не переписывать.
- `ozon_fbs_import` остаётся `enabled: false`, пока владелец явно не включит.
- Модуль не создаёт заказ, отгрузку, возврат и списание. Не удаляет документы.
- Не хранить покупателя, адрес, телефон, сырой ответ и финансы.
- Не печатать `OZON_API_KEY` и не менять подписки Ozon Push.
- Не выключать TopSeller и не править `logistics_sheet`, `daily_upd` и другие текущие автоматизации без отдельного согласия.
- Не включать цены и остатки МойСклад → Ozon.
- Не считать доставку выплатой и не возвращать списание в доступный остаток.
- Статусы и методы, которых нет в `docs/ozon/API.md` и `docs/ozon/STATUS_MAP.md`, не вызывать и не дописывать по памяти.
