# Печатные формы МойСклад

Шаблоны, которые загружаются в МойСклад руками: через JSON API шаблоны можно только
читать, загрузить или изменить нельзя (`docs/moysklad-api/workbook/_workbook_print_templates.md`).

## Стикер курьера 120×75 — заказ покупателя

`courier_label_120x75.xls` — термостикер на заказ: всё, что нужно курьеру.

| На стикере | Откуда | Заполнено* | Влезает целиком* |
|---|---|---|---|
| ЗАКАЗ № … от дд.мм.гггг | номер и дата заказа | 100 % | |
| Получатель | покупатель (контрагент заказа), 1 строка, длинное имя ужимается | 100 % | 99 % |
| Телефон | доп. поле «Номер телефона», если пусто — телефон из карточки покупателя | 86 % | |
| Адрес | адрес доставки заказа, если пусто — фактический адрес из карточки покупателя | 89 % | 99 % |
| К адресу | комментарий к адресу доставки: вход, часы, контакт, «Получатель: …» у заказов с сайта | 29 % | 91 % |
| Комментарий | комментарий заказа: у заказов с сайта — способ доставки, ПВЗ, получатель | 28 % | 94 % |
| Сумма | сумма заказа | 100 % | |
| Мест: ____ | вписать от руки при сборке | | |
| Отправитель | ваша организация из заказа и её телефон | 100 % | |

\* по 800 заказам с 17.08 по 04.11.2026. Строк на каждое поле дано столько, чтобы текст
влезал целиком почти всегда; длиннее — обрежется по краю стикера. Пустое поле печатается
пустой строкой.

Доп. поля «Тип доставки» и «Оплата» на стикер не вынесены: в этих 800 заказах они
заполнены в 7 и 4 заказах. Способ доставки у заказов с сайта виден в комментарии.
Имя доп. поля телефона зашито в `courier_label.py` (`ATTR_PHONE`) и должно совпадать
с МойСклад буква в букву.

### Загрузить в МойСклад

1. Откройте любой заказ покупателя → **Печать** → **Настроить…** и добавьте свой шаблон
   файлом `courier_label_120x75.xls`. Имя задайте, например, «Стикер курьера 120х75».
2. Напечатайте один заказ в PDF и проверьте размер страницы. Если он 120×75, печатайте на термопринтер
   в масштабе 100 % («Фактический размер»), бумага в драйвере — 120×75.
3. Если PDF вышел на A4: размер стикера в `.xls` записан в настройках принтера (запись PLS),
   а их понимают не все конвертеры. Тогда нужно взять настройки страницы из шаблона, который
   у вас уже печатается на этот принтер (например, `etiketka_75x120`).

После загрузки хаб видит шаблон по имени: `python -m hub templates orders`,
`GET /api/orders/{ref}/print?template=Стикер курьера 120х75`.

### Поменять стикер

Правьте `courier_label.py`: поля и надписи, сетку `COLS_MM` / `ROWS_MM` (в сумме 114 × 71 мм —
стикер минус поля), шрифты в `build()`. Пересобрать:

```bash
pip install xlwt
python print_templates/courier_label.py
```

Затем загрузите новый файл в МойСклад вместо старого.

Выражения `${…}` — разметка jXLS, как в стандартных шаблонах МойСклад
(`GET /download-template/order.xls`, `invoice-stamp-sign.xls`). В заказе покупателя
`o.sourceAgentRequisite` — покупатель, `o.targetAgentRequisite` — ваша организация.
Доп. поля — `formatter.findAttribute(o, "Имя").valueString` (строка) или `.entityValue.name`
(справочник), адрес доставки — `o.addressFull`, комментарий к нему — `o.address.comment`,
комментарий заказа — `o.description`, фактический адрес покупателя —
`o.sourceAgentRequisite.actualAddress` (справка МойСклад «Основные формулы вывода данных
из документа», «Формулы вывода данных контрагента из документа»).

## Лист A4 на коробку — отгрузка

`shipment_a4.xls` — то же, что на стикере, плюс состав заказа. Загружается в **Отгрузки**:
откройте любую отгрузку → **Печать** → **Настроить…** → добавить шаблон, например
«Лист на коробку A4». Печатается на A4, по ширине — один лист.

| На листе | Откуда | Заполнено** |
|---|---|---|
| ЗАКАЗ № … (крупно) | номер заказа покупателя, из которого сделана отгрузка | 97 % отгрузок связаны с заказом |
| Отгрузка № … от … | номер и дата отгрузки: номера отгрузок (02998) не совпадают с номерами заказов | 100 % |
| Получатель, Телефон | покупатель и телефон из его карточки | 100 % / 86 % |
| Адрес | адрес доставки отгрузки, если пусто — фактический адрес из карточки покупателя | 91 % |
| К адресу | комментарий к адресу доставки отгрузки | 40 % |
| Комментарий | комментарий отгрузки, если пусто — комментарий заказа | 26 % |
| Сумма, Мест: ____, Отправитель | сумма отгрузки, места от руки, ваша организация | |
| Состав заказа | № · наименование · количество · ед. · ✓ — все позиции отгрузки | |

\** по 600 отгрузкам с 04.09 по 05.11.2026. В отгрузке комментарий почти всегда пустой (1 %),
а в заказе он есть у 25 % — поэтому он берётся из заказа. Позиций в отгрузке: медиана 3,
99 % — до 15; на первый лист помещается около 20, дальше таблица переходит на второй.
Длинное наименование ужимается в одну строку (97 % названий — до 70 знаков).

Не подтверждено документацией: номер и комментарий заказа взяты как `o.customerOrder.name`
и `o.customerOrder.description` — точной формулы в справке не нашлось. Если на пробной печати
номер заказа пустой, а у отгрузки заказ есть, поправьте `ORDER` в `shipment_a4.py`.

В отгрузке стороны наоборот, чем в заказе: `o.targetAgentRequisite` — покупатель,
`o.sourceAgentRequisite` — ваша организация (стандартный УПД МойСклад: «Продавец» — source,
«Покупатель» — target). Позиции — цикл `<jx:forEach items="${o.shipments}">`, как в стандартном
«Товарном чеке» (`GET /download-template/demand_check.xls`).

Пересобрать: `python print_templates/shipment_a4.py`.

## Договор поставки — Договоры

`contract_supply.xls` — договор поставки товаров (6 листов A4) с логотипом CULTURA COFFEE
ROASTERS. Загружается в **CRM → Договоры**: откройте любой договор → **Печать** → **Настроить…** →
добавить шаблон. Печатается из договора: покупатель и его счёт — те, что указаны в договоре.

| В договоре | Откуда |
|---|---|
| № и дата | номер и дата договора в МойСклад (ПК-ДД/ММ/ГГ-NN) |
| Преамбула покупателя | полное наименование из карточки; ООО — «в лице Генерального директора ____, действующего на основании Устава», ИП — без этого |
| Реквизиты покупателя | юр. и факт. адрес, ИНН/КПП, ОГРН или ОГРНИП, телефон, e-mail — из карточки; р/с, банк, к/с, БИК — счёт покупателя из договора |
| Должность в подписи | «Генеральный директор» или «Индивидуальный предприниматель» по типу покупателя |
| Поставщик | текстом из договора: ИП Краснояров Д. С., Седова 23 / Курляндская 49, ТБанк |
| п. 5.5, срок оплаты | пропуск «______» — вписать от руки |
| ФИО директора покупателя, оператор ЭДО, КПП ОП, лицензия | пропуски — в МойСклад таких полей нет |

Текст — `contract_supply.txt`: правится как обычный текст, `{{ИМЯ}}` — поля из `FIELDS`
в `contract_supply.py`. Высоты строк и разрывы листов генератор считает сам по метрикам Arial:
в .xls строки не растягиваются под текст, а раздел 11 должен стоять целиком на одном листе.
Печать — «по ширине один лист»: если конвертер посчитает колонки шире, лист чуть ужмётся.

Пересобрать (нужен LibreOffice — он переводит книгу с картинкой в .xls):

```bash
pip install openpyxl pillow
python print_templates/contract_supply.py
```

Поля — как в стандартном шаблоне МойСклад «Договор» (`GET /download-template/contract.xls`):
`o.name`, `o.moment`, `o.agent.requisite.*`, `o.agent.contact.*`, тип покупателя —
`o.agent.getCompanyType().name().equals("INPR")`. Не подтверждено стандартным шаблоном:
`o.agent.requisite.actualAddress` (из справки «Формулы для шаблона договора») и месяц словами
`%1$tB` (так дату пишет стандартный УПД МойСклад) — проверить на первой печати.
